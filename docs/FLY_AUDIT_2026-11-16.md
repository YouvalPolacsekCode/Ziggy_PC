# Fly.io audit — 2026-11-16

Read-only audit of everything in this repo that defines or references a Fly.io
app. **Source is the repo only:** nobody ran `fly` against the live account, so
check the "verify live" column before acting on it.

## What the repo defines

- **One `fly.toml`:** `relay/fly.toml` (app `ziggy-relay`). There are no other
  fly.toml files, `fly launch` configs or `[processes]` groups.
- **No CI/CD deploys.** `.github/workflows/tests.yml` runs tests only and says
  outright that it is not a deploy. `catalog-auto-merge.yml` merges catalog PRs.
  Every deploy is a manual `fly deploy` from the laptop (see
  `docs/CANARY_REBUILD_RUNBOOK.md`, `docs/company-os/STATUS.md`).
- **No multi-region setup anywhere.** Nothing sets more than one region, and no
  service runs in more than one region, so there is nothing redundant to remove.

The other apps below appear only in docs (mostly
`docs/company-os/ARCHITECTURE.md`, the 2026-09-18 estate audit). Their configs
live in other repos.

## Stale references (no cost, but misleading)

- `registry.fly.io/ziggy-relay:ziggy-app` in `AUDIT.md` and
  `docs/RUNBOOK_HETZNER_MIGRATION.md`, and `registry.fly.io/ziggy:latest` in
  `tests/test_ha_installer.py`. These date from the v1 cloud-VM model. Hubs now
  build their image locally (`scripts/canary/hub-bootstrap.sh`), and the relay no
  longer provisions VMs (`docs/ARCHITECTURE_RELAY.md`). Old images left in the
  Fly registry can be pruned.
